## Week 9 Keyword

### ▶ Swagger / OpenAPI

- **OpenAPI**는 REST API의 엔드포인트와 요청·응답 형식을 YAML이나 JSON으로 기술하는 표준 명세임. **Swagger**는 이 명세를 문서화하고 테스트하는 도구 모음임.
- Spring에서는 `springdoc-openapi`를 추가하면 Swagger UI가 자동 생성되어, 프론트엔드가 화면에서 API를 바로 호출해볼 수 있음.
- 코드와 문서가 함께 관리되는 것이 장점이고, 어노테이션 때문에 코드가 지저분해지는 것이 단점임.

### ▶ 단위 테스트

- 함수나 클래스 같은 가장 작은 단위를 DB, 네트워크 등 외부 의존성과 분리해 검증하는 테스트임.
- 빠르고 실패 원인을 바로 찾을 수 있어서 리팩토링할 때 안전망 역할을 함.
- 모듈끼리 연결했을 때 생기는 문제는 잡지 못함. Java에서는 주로 **JUnit 5**와 **Mockito**를 사용함.

### ▶ 통합 테스트

- 여러 모듈과 DB, 외부 API를 실제로 연결한 상태에서 함께 잘 동작하는지 검증하는 테스트임.
- 설정 오류나 쿼리 오류처럼 연결 지점에서 생기는 버그를 잡을 수 있지만, 느리고 환경 구성이 복잡함.
- Spring에서는 `@SpringBootTest`, Testcontainers 등으로 작성함.

### ▶ Mock, Stub

- 둘 다 테스트에서 실제 객체를 대신하는 **테스트 더블**임.
- **Stub**은 미리 정한 값을 반환해 결과 상태를 검증하는 데 쓰고, **Mock**은 메서드가 몇 번, 어떤 인자로 호출됐는지 행위를 검증하는 데 씀.
- Mock을 남용하면 테스트가 내부 구현에 묶여서 코드를 조금만 바꿔도 깨지기 쉬움.

### ▶ given-when-then

- 테스트를 준비, 실행, 검증 세 단계로 나눠 작성하는 BDD 패턴임.
- 테스트가 무엇을 검증하는지 읽기 쉽고, 테스트 코드 자체가 요구사항 명세 역할을 함.
- 같은 구조를 AAA 패턴, 즉 **Arrange-Act-Assert**라고도 부름.

### ▶ 회귀 테스트

- 코드 수정 후 원래 잘 되던 기능이 망가지지 않았는지 기존 테스트를 다시 실행해 확인하는 테스트임.
- 보통 GitHub Actions 같은 CI로 자동화해서 PR을 올릴 때마다 전체 테스트를 실행함.
- 테스트가 쌓일수록 실행 시간과 관리 비용이 늘어나는 것이 단점임.
