# 핵심 키워드 정리

## PK, FK란?

PK (기본키)
 테이블에서 각 행을 유일하게 식별하는 컬럼
 NULL 불허, 값 중복 불가
 테이블당 1개만 지정 가능

FK (외래키)
 다른 테이블의 PK를 참조하는 컬럼
 테이블 간 관계를 성립시킴
 FK 값은 참조 테이블에 존재하는 값이거나 NULL이어야 함

 장점: 데이터 무결성 보장, 중복 삽입/삭제 시 자동 제약 검사
 단점: 삽입/삭제 순서 제약 발생, 과도한 FK는 JOIN 비용 증가

## ERD란?

Entity Relationship Diagram. 테이블, 속성, 관계를 도식화한 것.

설계 단계에서 전체 스키마 구조를 한눈에 파악
팀원 간 커뮤니케이션 및 정규화 검증에 사용

---

## 연관관계란? 그리고 연관관계를 설정하는 방법은?

두 테이블(엔티티) 간의 논리적 연결. 실무에서는 FK 제약으로 물리적 구현.

 1:1: 한쪽 테이블에 FK + UNIQUE 제약
 1:N: N쪽(자식) 테이블에 FK 컬럼 추가 (가장 일반적)
 N:M: 두 테이블 PK를 각각 FK로 갖는 중간(연결) 테이블 생성

 1:1 → FK+UNIQUE, 1:N → N쪽에 FK,N:M → 중간 테이블 생성이 관계 설정의 기본 원칙

---

## 정규화란?

데이터 중복 제거, 삽입/갱신/삭제 이상 방지를 위해 테이블을 분해하는 과정.

 1NF : 원자값만 허용
 2NF : 부분 함수 종속 제거
 3NF : 이행 함수 종속 제거 
 BCNF : 모든 결정자가 후보키가 되도록 


 장점: 데이터 일관성, 저장 공간 절약, 이상현상 방지
 단점: 테이블 수 증가 → JOIN 빈도 증가 → 조회 성능 저하 가능

---

## 반정규화란?

정규화된 테이블을 의도적으로 통합 및 중복시켜 조회 성능을 높이는 기법.읽기가 많고 쓰기가 적은 시스템에서 유효.

방법: 컬럼 중복 저장, 파생 컬럼, 테이블 병합, 테이블 분할, 중복 테이블 생성
장점: JOIN 감소로 조회 속도 향상
단점: 데이터 정합성 관리 부담 증가, 저장 공간 증가


---

## DB에서의 상속 관계 표현은 어떻게 하는가?

RDB는 상속 직접 지원x

1. 단일 테이블
   - 부모+자식 속성을 한 테이블에 통합, 구분 컬럼으로 타입 구분
   - 조회 빠름, NULL 컬럼 많아짐

2. 조인
   - 부모/자식 테이블 분리, 자식은 부모 PK를 FK 겸 PK로 가짐
   - 정규화됨, 조회 시 JOIN 필요

---

## 인덱스란?

테이블 조회 속도를 높이기 위한 별도의 자료구조. 특정 컬럼에 대한 정렬된 포인터 목록을 유지해 전체 스캔 없이 빠르게 데이터 위치를 찾음.

- 장점: SELECT/WHERE/JOIN/ORDER BY 성능 대폭 향상
- 단점: INSERT/UPDATE/DELETE 시 인덱스도 갱신 필요 → 쓰기 성능 저하, 저장 공간 추가
